# Parallel Image Processing (DAG Task Pipeline)

Многопоточный конвейер обработки изображений на Java с использованием **собственного пула потоков (`CustomThreadPool`)** и **графа зависимостей задач (DAG)** без глобальных барьеров.

## Что делает программа

На вход подаётся цветное RGB-изображение (PNG/JPEG, 8 бит на канал). Изображение разбивается на независимые тайлы (плитки/полосы), и из него параллельно строятся **пять производных изображений**:

1. **Оттенки серого (`gray.png`)** — перевод яркости по стандарту BT.601:
   $$\text{Gray} = 0.299 R + 0.587 G + 0.114 B$$
2. **Разложение в YCbCr (`ycbcr_y.png`, `ycbcr_cb.png`, `ycbcr_cr.png`)** — перевод в цветовое пространство JPEG (полный диапазон `0–255`), каждый канал сохраняется как отдельное одноканальное изображение.
3. **Обратный перевод YCbCr → RGB (`ycbcr_roundtrip.png`)** — восстановление цветного RGB-изображения по округлённым каналам `Y`, `Cb`, `Cr`.
4. **Бочкообразная дисторсия (`distort.png`)** — нелинейное радиальное искажение с обратным отображением координат и билинейной интерполяцией по 4 соседним пикселям:
   $$x_s = c_x + (x - c_x)(1 + k r^2), \quad y_s = c_y + (y - c_y)(1 + k r^2)$$
5. **Карта границ по Собелю (`sobel.png`)** — вычисление модуля градиента яркости $\sqrt{G_x^2 + G_y^2}$ свёрткой $3 \times 3$ по серому изображению с повтором краевых пикселей.

Дополнительно в выходную папку записывается файл **`report.json`** с параметрами запуска, общим временем работы и суммарным временем выполнения каждого вида задач в миллисекундах.

## Архитектура и параллелизм

* **Собственный пул потоков (`CustomThreadPool`):** реализован с нуля на базе `ReentrantLock`, `Condition`, `AtomicInteger` и `ArrayDeque<Task>` без использования `ExecutorService`, `ForkJoinPool` или параллельных стримов.
* **Отслеживание зависимостей без глобальных барьеров:**
  * Задачи `GRAY`, `YCBCR` и `DISTORT` зависят только от исходного изображения и поступают в очередь сразу после старта.
  * Тайл `(r, c)` задачи `ROUNDTRIP` запускается сразу после готовности соответствующего тайла `(r, c)` задачи `YCBCR`.
  * Тайл `(r, c)` оператора `SOBEL` запускается автоматически, как только готовы его соседние тайлы `GRAY` в окрестности $3 \times 3$, не дожидаясь завершения всего серого изображения.
  * Задачи сохранения каждого выходного файла (`SAVE`) запускаются параллельно по мере готовности всех тайлов соответствующего фильтра.
* **Побитовая идентичность:** все промежуточные вычисления выполняются в `double` с округлением к ближайшему целому (`Math.round`) и ограничением в диапазон `[0, 255]`, благодаря чему последовательный (`seq`) и параллельный (`par`) режимы дают побитово одинаковый результат.

## Структура проекта

```text
├── Main.java                  # Точка входа, разбиение на тайлы, сборка графа задач и генерация report.json
├── FilteringImgService.java   # Математическая реализация 5 фильтров обработки изображения
├── TilePosition.java          # Координаты границ тайла (xStart, xEnd, yStart, yEnd)
└── threadPool/
    ├── CustomThreadPool.java  # Собственный пул потоков с очередью задач и условными переменными
    ├── Task.java              # Узел графа задач с атомарным счётчиком зависимостей и списком зависимых задач
    └── TaskType.java          # Перечисление видов задач (GRAY, YCBCR, ROUNDTRIP, DISTORT, SOBEL, SAVE)
```

## Сборка и запуск

### 1. Компиляция
```bash
javac -d bin Main.java FilteringImgService.java TilePosition.java threadPool/*.java
```

### 2. Запуск
```bash
java -cp bin Main --input Hardi.png --out result/ --mode par --threads 8 --strip 64 --k 0.4
```

### Параметры командной строки

| Параметр | Описание | Значение по умолчанию |
|---|---|---|
| `--input` | Путь к входному изображению (PNG/JPEG) | `Hardi.png` |
| `--out` | Папка для сохранения выходных файлов и `report.json` | `result` |
| `--mode` | Режим работы: `par` (параллельный) или `seq` (последовательный эталон) | `par` |
| `--threads` | Количество рабочих потоков в пуле | число ядер CPU |
| `--strip` | Размер стороны тайла (в пикселях) | `256` |
| `--k` | Коэффициент бочкообразной дисторсии | `0.4` |
